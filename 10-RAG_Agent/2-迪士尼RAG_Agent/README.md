# 迪士尼 RAG 助手

基于阿里云百炼多模态向量模型的迪士尼知识库问答示例。先把 Word 文档和图片编码进 FAISS，查询时用同一模型把问题向量化，按 L2 距离检索，再把最相关的文本交给大模型生成答案。问题里带图片或视频关键词时，额外返回距离最近的媒体路径。

## 目录

```
2-迪士尼RAG_Agent/
├── 1-disney_build_index.py    # 解析知识库、生成向量、写入 FAISS
├── 2-disney_query.py          # 加载索引、检索、调用大模型回答
├── requirements.txt
└── disney_knowledge_base/
    ├── 1-上海迪士尼门票规则.docx
    ├── 2-迪士尼老人票价规定.docx
    ├── 3-迪士尼乐园游玩攻略清单.docx
    ├── 4-上海迪士尼乐园酒店会员制度.docx
    └── images/
        ├── 1-聚在一起说奇妙.jpg
        └── 2-万圣节.jpeg
```

向量索引不放在本目录。`faiss.write_index` / `faiss.read_index` 在 Windows 上打不开中文路径，两个脚本都把索引写到纯英文目录：

- `D:\faiss\disney_rag\disney_index.faiss`
- `D:\faiss\disney_rag\disney_metadata.json`

元数据里的图片路径是建库时的绝对路径。本次查询加载的是旧索引，日志里的图片路径仍是 `CASE-迪士尼RAG助手`，和当前目录名不一致。需要和当前知识库对齐时，先重新跑建库脚本。

## 1-disney_build_index.py

入口是 `build_and_save()`。它扫描 `disney_knowledge_base`，把文本块和图片编成向量，写入 `IndexFlatL2`。

文本、图片、视频三种数据的向量都使用同一种 Embedding 模型：`tongyi-embedding-vision-plus`，接口是 `dashscope.MultiModalEmbedding.call`。三者只是输入字段不同（`text`、`image`、`video`），向量落在同一空间，才能放进同一个 FAISS 索引做 L2 检索。查询脚本给用户问题做向量时也用这个模型。


| 函数                    | 作用                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------- |
| `parse_docx`          | 按文档 body 顺序读取段落；表格转成 Markdown 表格文本                                                          |
| `split_text`          | 固定长度切分，`CHUNK_SIZE=500`，`CHUNK_OVERLAP=50`                                                  |
| `get_text_embedding`  | 调用 `tongyi-embedding-vision-plus`，输入为 `{"text": ...}`                                       |
| `get_image_embedding` | 图片转 base64 data URL 后调用同一模型，输入为 `{"image": ...}`                                            |
| `get_video_embedding` | 调用同一模型，输入为 `{"video": ...}`，多帧向量取平均。`VIDEO_KNOWLEDGE` 为空，调用处已注释，当前建库不入库视频 |


处理顺序：

1. 遍历知识库根目录下的 `.docx`，跳过子目录和隐藏文件。每篇文档切成多个 chunk，每个 chunk 一条元数据：`id`、`source`（文件名）、`type=text`、`content`。
2. 遍历 `images/` 下的 png、jpg、jpeg、gif、bmp。图片不再做 OCR，语义由多模态向量承担。元数据为 `type=image`，并保存图片绝对路径。
3. 全部向量 `astype("float32")` 后 `index.add`，写出 FAISS 文件和 JSON 元数据。
4. 打印文本、图片、视频条数，以及每条知识的 id、类型、来源和内容。

本次查询加载到的索引共 11 条：9 条文本、2 条图片、0 条视频。

## 2-disney_query.py

入口加载 `D:\faiss\disney_rag` 下的索引和元数据，然后依次跑三条内置问题。核心函数是 `rag_ask`。


| 函数                       | 作用                                                      |
| ------------------------ | ------------------------------------------------------- |
| `load_index`             | 读取 FAISS 和 JSON，打印记录条数                                  |
| `get_text_embedding`     | 用 `tongyi-embedding-vision-plus` 把用户问题编成向量              |
| `distance_to_similarity` | L2 距离转为相似度：`1 / (1 + distance)`，越大越相似                   |
| `search_with_details`    | 对全部记录检索，按距离打印排名、id、类型、相似度、距离和内容前 45 字                   |
| `detect_media_intent`    | 关键词判断是否要图片或视频                                           |
| `rag_ask`                | 取 Top-k 文本拼进 Prompt，调用 `qwen-flash` 生成答案；命中媒体时把路径附在答案末尾 |


媒体意图只看关键词，不看向量：

- 图片：`图片`、`海报`、`照片`、`看看`、`长什么样`、`图`
- 视频：`视频`、`录像`、`影片`、`看一下`、`播放`

命中后，在对应类型里筛选 L2 距离小于 `MEDIA_DISTANCE_THRESHOLD`（3.0）的结果，取距离最小的一条。文本上下文与媒体匹配分开：Prompt 只用 `type=text` 的前 `k` 条（脚本里 `k=3`），图片和视频不进入背景知识，只在最终答案后追加路径。

Prompt 角色是迪士尼客服。背景知识带上来源文件名和相似度，模型为 `qwen-flash`，走 DashScope 的 OpenAI 兼容接口 `https://dashscope.aliyuncs.com/compatible-mode/v1`。

`__main__` 中的三条测试：

1. `我想了解一下迪士尼门票的退款流程`：无媒体关键词，只做文本检索。
2. `最近万圣节的活动海报是什么`：命中“海报”，返回距离更近的万圣节图片。
3. `聚在一起说奇妙的海报`：同样命中“海报”。这次索引里万圣节图片的距离（1.6392）小于“聚在一起说奇妙”那张图，所以附加的是万圣节图片。文本 Top-3 与海报内容也不对应，模型是在无关文本上生成的回答。
