1. 是什么：深思熟虑型架构

「深思熟虑式」智能体不追求单次即时回答，而是把研究任务拆成 感知 → 建模 → 推理 → 决策 → 报告 五个显式阶段。每个阶段用 LLM 产出结构化中间结果，写入共享状态，下一阶段再消费。

与反应式（Reactive）智能体对比：反应式偏「问一句答一句」；深思熟虑式偏「先想清楚再下结论」， 用多步推理换更高质量的投研输出。源码开头的模块说明也直接点明了这条主线：

深思熟虑式.py · 模块 docstring
"""
深思熟虑智能体（Deliberative Agent）- 智能投研助手

核心流程：
1. 感知：收集市场数据和信息
2. 建模：构建内部世界模型，理解市场状态
3. 推理：生成多个候选分析方案并模拟结果
4. 决策：选择最优投资观点并形成报告
5. 报告：生成完整研究报告
"""

2. 主流程：五阶段流水线

五个节点串行连接，入口为 perception，出口经 report 到达 END。

01

感知 Perception

收集市场概况、指标、新闻、行业趋势 → JSON

02

建模 Modeling

基于感知数据构建内部世界模型 → JSON

03

推理 Reasoning

生成 3 个差异化候选投资方案 → JSON 数组

04

决策 Decision

评估候选方案，选出最优观点 → JSON

05

报告 Report

综合前述结果，撰写完整投研报告 → 文本

  DEC --> REP[report 报告]
  REP --> FIN([END])

  MOD -.写入.-> S2[(world_model)]

workflow.add_node("modeling", modeling)

代码里虽然定义了 router()，但当前图是用 add_edge 写死的线性边； 实际执行路径就是上图的单向流水线，并不走条件路由。

3. 状态机：定义、使用与流转

在 LangGraph 里，ResearchAgentState 不是「枚举几个状态名」那么简单， 而是整张图共享的一份数据黑板：入口写入初始值，每个节点读这份黑板、写回更新， 图沿着固定边推进，状态字段被逐步填满。

ResearchAgentState
class ResearchAgentState(TypedDict):
    """研究智能体的状态"""

    # 输入
    research_topic: str
    industry_focus: str
    time_horizon: str

    # 处理状态
    perception_data: Optional[Dict[str, Any]]
    world_model: Optional[Dict[str, Any]]
    reasoning_plans: Optional[List[Dict[str, Any]]]
    selected_plan: Optional[Dict[str, Any]]

    # 输出
    final_report: Optional[str]

    # 控制流
    current_phase: Literal[
        "perception", "modeling", "reasoning", "decision", "report"
    ]
    error: Optional[str]
输入
research_topic industry_focus time_horizon
中间结果
perception_data world_model reasoning_plans selected_plan
输出
final_report
控制
current_phase error

状态如何使用

可以把 state 分成三类职责理解：

  • 只读输入：research_topic / industry_focus / time_horizon 在 run_research_agent 里写入后，各阶段 Prompt 都会读它们，一般不再改写。
  • 阶段产物（读写）：节点从上游字段取数组装 Prompt，再把 LLM 结果写进本阶段字段。 例如建模读 perception_data，写出 world_model。
  • 控制字段：current_phase 标记「逻辑上走到哪一步」； error 记录异常信息。当前实现里，图的真实跳转靠 add_edge， 不靠 current_phase 做条件分支。

节点对状态的标准用法是「整包传入 → 覆盖写回」：

节点读写状态的统一写法
# 读：从 state 取字段
input_data = {
    "research_topic": state["research_topic"],
    "perception_data": json.dumps(state["perception_data"], ...),
}

# 写：浅拷贝后覆盖本阶段字段，并推进 current_phase
return {
    **state,
    "world_model": result,
    "current_phase": "reasoning",
}
关键点：LangGraph 在每个节点执行后，用节点返回值更新图状态，再把最新 state 交给下一个节点。 所以后面的阶段天然能看到前面已经写入的字段，而不需要全局变量。

状态如何流转

有两层「流转」要分开看：一层是图节点流转（谁执行下一个函数）， 一层是状态字段流转（哪几个字段从 None 变成有值）。 

stateDiagram-v2
  [*] --> perception: initial_state\n三要素已填\n其余为 None

  perception --> modeling: 写入 perception_data\ncurrent_phase=modeling
  modeling --> reasoning: 写入 world_model\ncurrent_phase=reasoning
  reasoning --> decision: 写入 reasoning_plans\ncurrent_phase=decision
  decision --> report: 写入 selected_plan\ncurrent_phase=report
  report --> [*]: 写入 final_report\ncurrent_phase=completed

图 3a · current_phase 与字段填充的同步推进

时刻 图上位置 state 发生了什么
启动 尚未进入节点 构造 initial_state：三要素有值；中间结果 / 报告为 None；current_phase="perception"；error=None
感知结束 perception → modeling 写入 perception_data；current_phase 改为 modeling
建模结束 modeling → reasoning 写入 world_model；phase → reasoning
推理结束 reasoning → decision 写入 reasoning_plans；phase → decision
决策结束 decision → report 写入 selected_plan；phase → report
报告结束 report → END 写入 final_report；phase 记为 completed；invoke 返回完整 state

图 3b · 状态是「累积填充」而不是「每步清空」

因此到报告阶段时，Prompt 可以同时拿到 perception_data + world_model + selected_plan： 它们都还在同一份 state 里。这也是深思熟虑式能「综合前文再写报告」的直接原因。

初始状态：流转的起点
initial_state = {
    "research_topic": topic,
    "industry_focus": industry,
    "time_horizon": horizon,
    "perception_data": None,
    "world_model": None,
    "reasoning_plans": None,
    "selected_plan": None,
    "final_report": None,
    "current_phase": "perception",
    "error": None,
}
result = agent.invoke(initial_state)  # 结束后 result 即最终 state

异常时状态怎么变

  • LLM 调用失败：节点 catch 后写入 error，并把 current_phase 留在当前阶段。
  • 上游字段缺失：如建模发现没有 perception_data，写 error，并把 phase「逻辑回退」到上一阶段名。
  • 但图边仍是固定的 modeling → reasoning；所以字段回退 ≠ 图上回跳。 真正要重试/回跳，需要改成条件边（例如挂上 router）。
异常写回示例（感知阶段）
except Exception as e:
    return {
        **state,
        "error": f"感知阶段出错: {str(e)}",
        "current_phase": "perception",
    }

各阶段期望的结构化输出

阶段 状态字段 主要字段（Prompt / Pydantic 约定）
感知 perception_data market_overview, key_indicators, recent_news, industry_trends
建模 world_model market_state, economic_cycle, risk_factors, opportunity_areas, market_sentiment
推理 reasoning_plans plan_id, hypothesis, analysis_approach, expected_outcome, confidence_level, pros, cons

文件中还定义了 PerceptionOutput 等 Pydantic 模型，并 import 了 PydanticOutputParser，但当前节点实际使用的是 JsonOutputParser / StrOutputParser，Pydantic 模型主要起「字段契约文档」作用。

4. 数据流：阶段间如何传值

每个阶段的 Prompt 会注入「研究三要素」，并逐步叠加上游产物（JSON 字符串化后塞进模板）。

flowchart LR
  IN["topic / industry / horizon"] --> P
  P["perception_data"] --> M
  M["world_model"] --> R
  R["reasoning_plans"] --> D
  P --> Rep
  M --> Rep
  D["selected_plan"] --> Rep
  Rep["final_report"]

图 3 · 中间结果依赖关系

以建模阶段为例：先校验上游 perception_data，再把它序列化进 Prompt：

modeling · 依赖校验与输入组装
if not state.get("perception_data"):
    return {
        **state,
        "error": "建模阶段缺少感知数据",
        "current_phase": "perception",
    }

input_data = {
    "research_topic": state["research_topic"],
    "industry_focus": state["industry_focus"],
    "time_horizon": state["time_horizon"],
    "perception_data": json.dumps(
        state["perception_data"], ensure_ascii=False, indent=2
    ),
}
节点 Prompt 输入变量 前置校验
perception research_topic, industry_focus, time_horizon —
modeling 三要素 + perception_data 缺少感知数据 → 记 error，phase 回退到 perception
reasoning 三要素 + world_model 缺少世界模型 → 回退 modeling
decision 三要素 + world_model + reasoning_plans 缺少候选方案 → 回退 reasoning
report 三要素 + perception_data + world_model + selected_plan 缺少选定方案 → 回退 decision
注意：节点内部在缺数据时会把 current_phase 改回上一阶段，但图上的边是固定 A → B，并没有根据 current_phase 做条件跳转。 因此这些「回退」主要体现在状态字段上；在线性边上，异常更多是靠 try/except 写 error 后继续往下走（或抛错由上层捕获）。

5. 节点实现：统一的 LLM Chain 模式

五个节点函数结构高度一致，可抽象为：

flowchart LR
  A[取 Prompt 模板] --> B[组装 input_data]
  B --> C["prompt | llm | parser"]
  C --> D[invoke]
  D --> E[写回 state]

图 4 · 单节点内部步骤

感知阶段是最完整的「模板节点」示例：

perception · 完整节点逻辑
def perception(state: ResearchAgentState) -> ResearchAgentState:
    print("1. 感知阶段：收集市场数据和信息...")

    try:
        prompt = ChatPromptTemplate.from_template(PERCEPTION_PROMPT)

        input_data = {
            "research_topic": state["research_topic"],
            "industry_focus": state["industry_focus"],
            "time_horizon": state["time_horizon"],
        }

        chain = prompt | llm | JsonOutputParser()
        result = chain.invoke(input_data)

        return {
            **state,
            "perception_data": result,
            "current_phase": "modeling",
        }
    except Exception as e:
        return {
            **state,
            "error": f"感知阶段出错: {str(e)}",
            "current_phase": "perception",
        }

报告阶段唯一的差别是解析器换成字符串输出：

report_generation · 解析器差异
chain = prompt | llm | StrOutputParser()
result = chain.invoke(input_data)

return {
    **state,
    "final_report": result,
    "current_phase": "completed",
}
  • 前四个阶段用 JsonOutputParser，要求模型输出 JSON。
  • 报告阶段用 StrOutputParser，输出自然语言报告。
  • LLM 为 Tongyi(model_name="qwen-flash")，密钥来自环境变量 DASHSCOPE_API_KEY。
  • Prompt 文本不在 py 文件里硬编码，而是从 YAML 一次性加载。
启动时加载 Prompt
PROMPTS_FILE = Path(__file__).parent / "prompts" / "深思熟虑式_prompts.yaml"

def load_prompts() -> Dict[str, str]:
    with open(PROMPTS_FILE, "r", encoding="utf-8") as f:
        return yaml.safe_load(f)

_PROMPTS = load_prompts()
PERCEPTION_PROMPT = _PROMPTS["PERCEPTION"]

6. 图编译：StateGraph 装配

create_research_agent_workflow() 完成「建图 → 挂节点 → 连边 → compile」。 同文件里还有一个未挂接的 router，展示「按 current_phase 决定下一步」的思路：

router · 当前未挂到图上
def router(state: ResearchAgentState) -> str:
    if state.get("error"):
        return state["current_phase"]

    current = state["current_phase"]
    if current == "perception":
        return "modeling"
    elif current == "modeling":
        return "reasoning"
    elif current == "reasoning":
        return "decision"
    elif current == "decision":
        return "report"
    elif current == "report":
        return END
    else:
        return END

7. 入口与产物

run_research_agent

  • 编译工作流，构造 initial_state（中间字段均为 None，phase 为 perception）。
  • 打印 Mermaid 图（调试用）。
  • agent.invoke(initial_state) 同步跑完全程，返回最终 state。
run_research_agent
def run_research_agent(topic: str, industry: str, horizon: str) -> Dict[str, Any]:
    agent = create_research_agent_workflow()

    initial_state = {
        "research_topic": topic,
        "industry_focus": industry,
        "time_horizon": horizon,
        "perception_data": None,
        "world_model": None,
        "reasoning_plans": None,
        "selected_plan": None,
        "final_report": None,
        "current_phase": "perception",
        "error": None,
    }

    print(agent.get_graph().draw_mermaid())
    result = agent.invoke(initial_state)
    return result
