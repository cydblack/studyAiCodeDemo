1. 模块定位与分层

本脚本不实现投顾 Agent 本身，而是站在 Agent 之上做「测试与评估」： 用例定义 → 数据集同步 → 批量推理 → 评分 →（可选）实验对比。 Agent 能力来自动态加载的 1-hybrid_wealth_advisor_langgraph_langsmith.py 中的 run_wealth_advisor。

L0 · 配置

LangSmith Client

读环境变量，决定能否连云端做 Dataset / Experiment。

L1 · 数据

本地用例常量

反应式 / 深思熟虑 / 边界三类用例，合并为 ALL_TEST_CASES。

L2 · 评估

RunEvaluator

处理模式是否正确、回复是否覆盖期望关键词。

L3 · 编排

create / evaluate / compare

数据集准备、批量评估、单测、实验对比，由 __main__ 串联。

4. 测试用例数据

三类常量最终合并为 ALL_TEST_CASES，供 create_test_dataset 写入云端。

3 条

REACTIVE

简单查询：行情、组合占比、ETF 解释。期望 processing_mode=reactive。

3 条

DELIBERATIVE

复杂规划：衰退调仓、退休策略、教育金计划。期望 deliberative。

2 条

EDGE

空查询、超长查询。用 should_handle_error / should_handle 标记。

5. 辅助读取函数

_get_example_inputs

_get_example_inputs(example) → dict
作用
从 Example 对象或普通 dict 安全取出 inputs；失败返回空字典。
读取顺序
example.inputs → dict["inputs"] → 自身含 user_query → __dict__
被谁用
run_evaluation 内嵌的 test_function

_get_example_outputs

_get_example_outputs(example) → dict
作用
安全取出期望输出（outputs），供评估器读取期望模式与关键词。
被谁用
ProcessingModeEvaluator、ResponseCompletenessEvaluator
这两个函数不是业务逻辑，而是适配层：LangSmith SDK 在不同调用路径里可能传对象也可能传字典， 统一成 dict 后，上层评估与推理代码不必再分支。

6. 评估器

两者都继承 langsmith.RunEvaluator，实现 evaluate_run(run, example)，返回带 key / score / comment 的反馈字典。

  RUN["Run.outputs

final_response"]
  EX["Example.outputs
期望字段"]

  RUN --> PM["ProcessingModeEvaluator"]
  EX --> PM
  RUN --> RC["ResponseCompletenessEvaluator"]
  EX --> RC

  PM -->|"相等 → 1.0
不等 → 0.0"| S1["key: processing_mode"]
  RC -->|"命中关键词比例"| S2["key: response_completeness"]

图 5 · 两个评估器如何读 Run 与 Example 并打分

ProcessingModeEvaluator.evaluate_run

evaluate_run(run, example, **kwargs) → Dict
作用
比对实际 processing_mode 与期望是否一致（reactive / deliberative）。
得分
匹配 1.0；不匹配 0.0；未指定期望则 score=None（跳过有效计分）。

ResponseCompletenessEvaluator.evaluate_run

evaluate_run(run, example, **kwargs) → Dict
作用
检查 final_response 是否包含 should_contain 中的关键词（大小写不敏感）。
得分
命中数 / 期望数，区间 [0, 1]；无响应则为 0。

7. 核心 API 方法

7.1 create_test_dataset

create_test_dataset

create_test_dataset(dataset_name="wealth-advisor-test-dataset") → str | None
作用
确保云端存在数据集；若已有示例则直接复用；若空或不存在则写入 ALL_TEST_CASES。
关键 API
read_dataset / create_dataset / create_example / list_examples
返回
成功返回数据集名；Client 未初始化或异常时返回 None。
flowchart TD
  START(["create_test_dataset"]) --> CHK{client 存在?}
  CHK -->|否| FAIL1["打印错误 / 返回 None"]
  CHK -->|是| READ{"read_dataset 成功?"}
  READ -->|是且有示例| REUSE["直接返回 dataset_name"]
  READ -->|是但为空| ADD["写入 ALL_TEST_CASES"]
  READ -->|不存在| NEW["create_dataset"]
  NEW --> ADD
  ADD --> VERIFY["list_examples 验证数量"]
  VERIFY --> OK(["返回 dataset_name"])

图 6 · create_test_dataset 分支逻辑

7.2 run_evaluation

run_evaluation

run_evaluation(dataset_name, experiment_name=None, evaluators=None) → Dict | None
作用
对指定数据集跑一轮 LangSmith Experiment：推理 + 评分。
默认评估器
未传入时使用 ProcessingMode + ResponseCompleteness。
核心
内嵌 test_function，再调用 langsmith.evaluation.evaluate。

test_function（内嵌于 run_evaluation）

test_function(example: Example) → Dict[str, Any]
作用
把 Dataset 中的一条 example 转成 Agent 调用，并规范输出字段。
输出字段
final_response、processing_mode、query_type、error
空查询
不调用 Agent，直接返回错误占位结果（对应边界用例）。
flowchart TD
  IN(["example"]) --> PARSE["解析 inputs"]
  PARSE --> EMPTY{"user_query 为空?"}
  EMPTY -->|是| ERR["返回 error / unknown 模式"]
  EMPTY -->|否| CALL["run_wealth_advisor"]
  CALL --> NORM["规范化输出字典"]
  NORM --> OUT(["供 evaluate + 评估器使用"])
  ERR --> OUT

图 7 · test_function 内部流程

7.3 run_single_test

run_single_test

run_single_test(user_query, customer_id="customer1") → Dict
作用
不走 Dataset / evaluate，直接调一次 Agent，打印模式、耗时与响应预览。
关系
与批量评估共享 run_wealth_advisor；适合本地调试，不计入 Experiment。
返回
result、process_time、timestamp

7.4 compare_experiments

compare_experiments

compare_experiments(experiment_names: List[str]) → Dict | None
作用
拉取多个实验的 runs，按 feedback key 汇总平均分，用于版本对比。
数据源
client.list_runs(project_name=exp_name) + run.feedback_stats
返回
每个实验名 → total_runs + average_scores
flowchart LR
  E1["experiment A"] --> LIST["list_runs"]
  E2["experiment B"] --> LIST
  LIST --> AGG["按 feedback key 收集 score"]
  AGG --> AVG["计算平均值"]
  AVG --> OUT["comparison_results"]
